## 1. Условие и состав программы

Сад — прямоугольная карта с препятствиями. Два садовника независимо обходят доступные клетки и обрабатывают их. Первый идёт змейкой по строкам сверху вниз. Второй начинает с противоположного угла и идёт змейкой по столбцам или по строкам в обратном направлении. Входной файл задаёт начальные клетки, скорости, длительность обработки и возможность обхода. Препятствия и уже обработанные клетки пропускаются. Если подходящий путь занят, садовник ждёт освобождения или использует обход, когда он разрешён.

Решение собрано в одном проекте из трёх программ на C17.

| Программа | Роль |
| --- | --- |
| `garden4_server` | Хранит карту и позиции, проверяет правила перемещения, назначает действия и принимает результаты |
| `garden4_worker` | Имитирует действия одного садовника. Идентификатор 1 или 2 задаётся при запуске |
| `garden4_view` | Наблюдает за всем садом, показывает карту и события обоих садовников |

Сад — данные на сервере. Садовники представлены двумя самостоятельными клиентскими процессами, каждый со своим таймером. Наблюдатели запускаются отдельно от них. Все связи между приложениями идут по IPv4 TCP. IP и порт передаются через командную строку. В одном запуске сервер принимает до 24 одновременных подключений, включая садовников и наблюдателей.

| Уровень из требований | Как показать |
| --- | --- |
| 4–5 | Сервер в режиме `basic` и два садовника. У каждого собственные события, сервер выводит готовность и причину остановки |
| 6–7 | Сервер в режиме `watch`, два садовника и отдельный наблюдатель с общей картой |
| 8 | Несколько наблюдателей одновременно. Каждый может уйти или подключиться в середине сеанса и получить текущий снимок |
| Выше 8 | Садовник может отключиться и продолжить работу после запуска с тем же номером. При остановке сервера все подключённые клиенты получают итоговый код и завершаются |

## 2. Модель и синхронизация

Из ИДЗ3 перенесены чтение карты и правила маршрутов. Одна функция обхода в ширину считает достижимость, находит первый шаг к цели и перечисляет кандидатов для уступки дороги. При расчёте от стартов учитываются препятствия, а при поиске пути — также позиция и зарезервированная клетка другого садовника. При выключенных обходах шаг выбирается сначала по горизонтали, затем по вертикали. Для старта вне угла маршрут циклически сдвигается к стартовой клетке. По обработанной клетке можно пройти.

Сервер обрабатывает события сокетов в одном цикле `poll`. Он последовательно применяет изменения к карте, поэтому проверка свободной клетки и её резервирование образуют одну операцию. Во время перехода прежняя позиция остаётся занятой, а соседняя клетка назначения зарезервирована. Сервер меняет позицию или отмечает обработку только после подтверждения. Для каждого садовника одновременно активно максимум одно действие.

После того как подключились оба садовника, сервер выдаёт каждому доступное действие. Клиенты отмеряют задержку по `CLOCK_MONOTONIC` и могут завершать обработку и переходы в разное время. Сервер продолжает принимать подключения и подтверждения, пока клиенты ждут. Если одна клетка освобождается или обрабатывается, ожидающий садовник повторно проверяет свой путь.

Когда оба садовника ждут, а обходы разрешены, сервер проверяет, может ли один уступить дорогу. Он перебирает обходом в ширину клетки, куда садовник может отойти при неподвижном напарнике. Для каждой пробной позиции сервер проверяет, открывается ли напарнику путь к его текущей цели. Если подходящая клетка найдена, садовник отходит к ней обычными шагами и ждёт, пока второй садовник не обработает свою цель. После этого оба возвращаются к обычному порядку. В журнале отмечено, кто и куда уступил.

Сеанс завершается с кодом 0 после обработки всех достижимых клеток. Если все незавершившие садовники подключены, никто не может двигаться, а освободить дорогу указанным способом нельзя, сервер выводит код 2 и перечисляет необработанные клетки. При отключении садовника план уступки сбрасывается. Последняя подтверждённая позиция остаётся занятой, а резерв незавершённого перехода снимается. Оставшийся на связи садовник продолжает доступные ему действия.

## 3. Протокол и завершение

Сообщения — строки с переводом строки в конце. `read_line` сохраняет неполную строку между вызовами `recv` и извлекает несколько строк, если TCP доставил их одним блоком. Строка ограничена 1023 байтами без перевода строки. Порядок полей и числовые диапазоны проверяются при чтении. Сервер использует ограниченные буферы отправки и обслуживает частичные записи по готовности сокета. Если клиент перестаёт принимать данные и его очередь переполняется, сервер отключает этого клиента.

| Сообщение | Назначение |
| --- | --- |
| `WORK 1`, `WORK 2`, `WATCH` | Клиент регистрирует роль. Второе подключение с занятым номером садовника отклоняется |
| `ACT номер миллисекунды` | Сервер назначает действие. Координаты и вид действия передаются отдельным сообщением `INFO` |
| `DONE номер` | Садовник подтверждает окончание назначенного действия |
| `INFO текст`, `VIEW ...` | Событие и полный снимок. Снимки видят наблюдатели, садовник получает события своей роли |
| `LEFT строки столбцы карта` | Итоговая диагностика необработанных клеток: ещё доступна, либо недостижима из обоих стартов |
| `END код` | Сервер сообщает итог и заканчивает передачу |

При разрыве соединения сервер сохраняет подтверждённые изменения в памяти. Садовник запускается повторно с тем же номером и получает новое действие от последней подтверждённой позиции. При отключении посреди обработки клетка остаётся необработанной. Если `DONE` дошло до сервера перед разрывом, результат учитывается ровно один раз. Состояние сохраняется в рамках текущего процесса сервера.

По SIGINT или SIGTERM сервер прекращает приём подключений, отправляет итоговый снимок и `END`, затем закрывает сокеты. У клиента `poll` позволяет получить `END` даже в середине длинного действия. Сервер ждёт завершения обмена до одной секунды. Обычные клиенты выходят с кодом, который получили от сервера. При внезапной потере сервера без `END` клиент сообщает об обрыве и выходит с кодом 1.

| Код | Итог |
| --- | --- |
| 0 | Все достижимые клетки обработаны |
| 1 | Ошибка запуска, ввода или связи |
| 2 | Маршрут невозможно продолжить |
| 130 / 143 | Сеанс прерван SIGINT / SIGTERM |

## 4. Вход и консоль

Формат карты совпадает с ИДЗ3.

| Строка | Значение |
| --- | --- |
| 1 | Число строк и столбцов, стороны до 30 клеток |
| 2 | Длительность перехода первого, перехода второго и обработки. Каждое значение от 1 до 100 |
| 3 | `C` или `R` для маршрута второго по столбцам или по строкам, затем `1` для обходов либо `0` для запрета |
| 4 | Строка и столбец первого старта, затем строка и столбец второго. Нумерация с нуля |
| 5 | Длительность единицы времени в миллисекундах, от 0 до 1000 |
| Остальные | Карта `.` (доступная клетка) и `#` (препятствие) |

Наблюдатель выводит события по порядку и показывает компактные снимки карты со счётчиком и статусами. Каждая строка карты занимает одну строку терминала. Цифры 1 и 2 обозначают садовников, `+` — обработанную клетку, `#` — препятствие, `.` — необработанную клетку. Пропуск препятствия виден как отдельное событие. Список необработанных клеток с причинами выводится в конце сеанса. Режим `watch` сохраняет события, итоговую карту и статистику в `garden.log` в рабочей папке сервера.

## 5. Сборка и демонстрация

В папке задания `IDZ/IDZ4` в Linux или Ubuntu/WSL:

```bash
cmake --preset debug
cmake --build --preset debug
ctest --preset debug
```

В VS Code с открытой папкой задания в WSL можно выбрать пресет `debug` и запустить сборку через Ctrl+Shift+B. Каждая команда запуска ниже выполняется в отдельном терминале из папки задания. Сначала запускается сервер. После строки `READY` можно запускать клиентов.

```bash
./build/cmake-debug/garden4_server 127.0.0.1 5000 watch data/demo.txt
./build/cmake-debug/garden4_view 127.0.0.1 5000
./build/cmake-debug/garden4_view 127.0.0.1 5000
./build/cmake-debug/garden4_worker 127.0.0.1 5000 1
./build/cmake-debug/garden4_worker 127.0.0.1 5000 2
```

Для базового режима замените `watch` на `basic` и запустите только двух садовников. Для распределённого запуска серверу передаётся адрес сетевого интерфейса, клиентам — доступный IP сервера и тот же порт. Серверу можно передать порт `0`, и ОС выберет свободный порт. Его фактический номер появится в строке `READY`.

Для демонстрации переподключения остановите наблюдателя через Ctrl+C и повторите его команду. Затем так же остановите одного садовника и запустите его с тем же номером. Новый наблюдатель сразу покажет актуальный сад. Садовник продолжит с места, где его действия были подтверждены сервером. Ctrl+C в терминале сервера завершает весь сеанс.

При сборке из корня репозитория исполняемые файлы лежат в `build/cmake-debug/IDZ/IDZ4/`. Путь к демонстрационной карте из корня — `IDZ/IDZ4/data/demo.txt`.

### Показ на двух компьютерах

Соберите проект на обоих компьютерах. На компьютере A узнайте IPv4 сетевого интерфейса командой `ip -br -4 addr`. В примере ниже это `192.168.1.10`. Подставьте реальный адрес компьютера A во все четыре команды. С компьютера B должен быть доступен TCP-порт 5000 компьютера A.

На компьютере A в одном терминале запустите сервер с замедленной картой:

```bash
awk 'NR == 5 {$0 = 500} {print}' data/demo.txt > /tmp/idz4-demo.txt
./build/cmake-debug/garden4_server 192.168.1.10 5000 watch /tmp/idz4-demo.txt
```

После `READY` запустите садовника 1 в другом терминале компьютера A:

```bash
./build/cmake-debug/garden4_worker 192.168.1.10 5000 1
```

На компьютере B запустите наблюдателя и садовника 2 в отдельных терминалах:

```bash
./build/cmake-debug/garden4_view 192.168.1.10 5000
./build/cmake-debug/garden4_worker 192.168.1.10 5000 2
```

1. Остановите наблюдателя через Ctrl+C и снова запустите его. Он покажет текущую карту.
2. Остановите садовника 2, дождитесь сообщения об отключении у наблюдателя и снова запустите с номером 2. Наблюдатель покажет, что садовник продолжил работу.
3. Нажмите Ctrl+C в терминале сервера. Оба садовника и наблюдатель завершатся с кодом 130. В Bash результат можно посмотреть командой `echo $?`.

## 6. Проверки

Тесты запускаются через CTest. Каждый сценарий создаёт рабочую папку и поднимает настоящие TCP-подключения на свободном порту. Дополнительные зависимости для тестов не нужны.

| Сценарий | Что проверяется |
| --- | --- |
| `basic` | По отдельному выводу на садовника, наблюдение в этом режиме отключено |
| `demo`, `rows` | Змейка по столбцам и по строкам, итог 43 из 43 и 12 из 12 |
| `isolated`, `blocked` | Два достижимых старта и отдельная недостижимая клетка. Диагностика невозможности обхода с кодом 2 |
| `yield` | На карте `.#.. / .#.. / ....` один садовник отходит в сторону, второй продолжает маршрут. Итог 10 из 10, код 0 |
| `corridor` | При разрешённых обходах двум садовникам негде разойтись в коридоре 1×4. Итог 2 из 4, код 2 и координаты двух оставшихся клеток |
| `yield_reconnect` | Садовник отключается во время уступки. После запуска с тем же номером оба заканчивают обход, итог 10 из 10 |
| `viewers` | Несколько наблюдателей получают одинаковый итог после отключения и подключения в процессе |
| `reconnect` | Обрыв посреди обработки. Второй садовник продолжает работу. Первый повторяет незавершённое действие, обработка засчитывается один раз |
| `worker_move` | Обрыв посреди перехода. Первый возвращается к последней подтверждённой позиции и завершает переход после переподключения |
| `shutdown` | SIGINT и SIGTERM во время действий длиной 100 секунд. Два садовника и два наблюдателя получают `END`. Диагностика полной карты 30×30 доходит целиком |
| `invalid` | Отклонение переполнения при вводе и повторного номера садовника. Обработка команды наблюдателя, поступившей частями |

В Ubuntu/WSL прошли 13 из 13 тестов ИДЗ4 и 71 из 71 теста репозитория. Сборка ИДЗ4 с `-Werror`, AddressSanitizer и UndefinedBehaviorSanitizer также прошла все 13 сценариев. Дополнительно проверены журналы 150 запусков на случайных картах. Переходы шли только в соседние свободные клетки, препятствия не посещались, повторной обработки не было. Итоговые счётчики совпали с независимым расчётом достижимости.

Для сетевого прогона использованы два изолированных сетевых пространства Linux внутри одной WSL, соединённые виртуальной парой Ethernet. Сервер и садовник 1 работали в пространстве с IP `10.40.15.1`. Садовник 2 и наблюдатель подключались из пространства с IP `10.40.15.2`. Наблюдатель и садовник 2 были перезапущены во время сеанса. После SIGTERM сервер и три подключённых клиента завершились с кодом 143. Для показа на отдельных физических компьютерах используются команды из раздела 5.
